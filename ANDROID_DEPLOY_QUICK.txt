================================================================================
                   DEPLOY FROM YOUR PHONE (NO PC NEEDED)
================================================================================

Need the latest build while you're away from a computer? Every push to `main` triggers the GitHub Actions workflow, which now
uploads the newest debug APK as an artifact you can download on Android:

1. Open the GitHub app (or https://github.com) and navigate to this repository.
2. Tap the **Actions** tab → select the most recent successful **CI** run.
3. Scroll down to **Artifacts** and download `android-debug-apk` (GitHub delivers a `.zip`).
4. Use the built-in Files/Downloads app to extract the `.apk` inside the `.zip`.
5. Tap the extracted `.apk`, approve "Install unknown apps" if prompted, and it will update Drill Down on your device.

Because each run increments the `versionCode` before building, installing from the downloaded artifact always counts as a new up
date just like the USB workflow.

Need a fresh artifact but nothing changed locally? From the GitHub app/site open **Actions → CI**, select the latest run, tap the **⋯** menu, and choose **Re-run jobs**—GitHub will rebuild and post a new ZIP you can immediately download on the same phone.

Need to fix a failed phone-only install?
   • "Artifact not found" → Trigger a new CI run (push any commit or re-run the latest workflow) because GitHub cleans artifacts after 90 days.
   • "Can't open file" → Ensure you unzipped `android-debug-apk.zip`. The `.apk` inside installs normally once extracted.
   • "Install blocked" → Enable Settings → Apps → Special access → Install unknown apps for your browser/Files app.

================================================================================
                              FIRST TIME SETUP
================================================================================

If this is your first deployment run:

1. Phone Setup:
   - Settings > About Phone > Build Number (tap 7 times)
   - Settings > Developer options > Enable USB Debugging
   - Allow the security prompt on phone

2. Computer Setup:
   - Android SDK/NDK installed
   - ANDROID_HOME environment variable set
   - Keystore file created and gradle.properties updated

3. First Deploy:
   - Connect phone via USB
   - Double-click: DEPLOY_ANDROID.bat
   - Wait for build and install to complete

================================================================================
                           IF SOMETHING GOES WRONG
================================================================================

ERROR: "No Android device connected"
   Fix: 
   - Check USB cable connection
   - Enable USB Debugging on phone (Settings > Developer options)
   - Try different USB port
   - Restart phone

ERROR: "Build failed"
   Fix:
   - Run: gradlew --stop
   - Run DEPLOY_ANDROID.bat again

ERROR: "Installation failed"
   Fix:
   - Phone storage full? Clear some space
   - Run: adb uninstall de.dakror.quarry
   - Run DEPLOY_ANDROID.bat again

ERROR: "ADB not available"
   Fix:
   - Set ANDROID_HOME environment variable
   - Add %ANDROID_HOME%\platform-tools to PATH
   - Restart terminal/computer

================================================================================
                            USEFUL COMMANDS
================================================================================

Check connected devices:
   adb devices

View phone logs:
   adb logcat | findstr "quarry"

Uninstall app from phone:
   adb uninstall de.dakror.quarry

Just build (without deploy):
   gradlew android:assembleFullRelease

Manual install:
   adb install -r android\build\outputs\apk\full\release\android-full-release.apk

================================================================================
                              TIPS
================================================================================

• Always increment versionCode before deploying updates (the new script handles this automatically)
• versionCode must be higher than the previous version
• versionName is just for display (e.g., "v123", "1.0", etc.)
• Game saves are preserved when updating (same package name)
• To completely reinstall: uninstall first, then deploy
• The -r flag in adb allows reinstalling with the same signature
